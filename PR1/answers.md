# Ответы на вопросы к ПР1

1. Зачем нужна система контроля версий (Git)?
Чтобы не плодить бесконечные папки с названиями вроде «проект_финал», «проект_исправленный2» и так далее. Git хранит полную историю всех изменений. Если что-то сломалось, можно за пару секунд откатиться к рабочей версии. А при командной работе без него вообще никак: иначе разработчики постоянно перезаписывали бы код друг друга.

2. Чем отличаются команды git add и git commit?
Команда git add просто помечает файлы и скидывает их в так называемый «индекс» (зону подготовки). То есть мы говорим гиту: «Вот эти файлы пойдут в следующий сейв». А git commit уже делает сам снимок — берет все, что лежало в индексе, и намертво сохраняет это в историю с понятным комментарием.

3. Что такое коммит простыми словами?
Это сохраненная точка во времени (слепок проекта). У каждого коммита есть свой уникальный номер (хэш), автор, точное время создания и комментарий о том, что именно было сделано.

4. Для чего создают файл .gitignore?
В репозиторий не нужно заливать лишний мусор: временные системные файлы, кэш, тяжелые папки с библиотеками или приватные пароли. В .gitignore просто прописывают пути и расширения, которые Git должен игнорировать и не предлагать добавить в коммит.

5. В чем разница между Git и GitHub?
Git — это локальная консольная программа, которая работает на компьютере и следит за файлами. А GitHub — это сайт в интернете, куда репозиторий выгружают из консоли, чтобы делиться кодом, сдавать работы на проверку или работать в команде.
