# Ответы на вопросы к ПР14

1. **В чем разница между Fetch API и XMLHttpRequest? Какие преимущества предоставляет Fetch API?**  
Fetch API основан на промисах и хорошо работает с `async/await`, поэтому код обычно проще читать. `XMLHttpRequest` использует события и callback-подход. При этом XHR до сих пор удобен, например, когда нужен прогресс загрузки файла.

2. **Как обрабатываются ошибки в Fetch API и почему 404 не вызывает reject?**  
`fetch` делает reject в основном при сетевой ошибке или отмене запроса. Ответ 404 все равно является корректно полученным HTTP-ответом, поэтому нужно самостоятельно проверять `response.ok` или `response.status`.

3. **Какие HTTP-методы поддерживает Fetch API?**  
GET используется для получения данных, POST - для создания, PUT - для полной замены ресурса, PATCH - для частичного изменения, DELETE - для удаления. Fetch также позволяет использовать другие HTTP-методы при необходимости.

4. **Как работать с заголовками запроса и ответа?**  
Заголовки запроса передаются через поле `headers` в настройках `fetch`. Заголовки ответа читаются через `response.headers`. Часто используются `Content-Type`, `Authorization`, `Accept`, а также пользовательские заголовки.

5. **Разница между PUT и PATCH.**  
PUT обычно отправляет полное новое представление ресурса. PATCH передает только поля, которые необходимо изменить. PATCH удобнее для небольших частичных обновлений.

6. **Как реализовать авторизацию в Fetch API?**  
Basic Auth передается в заголовке `Authorization: Basic ...`. Bearer Token передается как `Authorization: Bearer <token>`. В OAuth2 приложение сначала получает access token, а затем также передает его в заголовке Bearer.

7. **Как отменить запрос?**  
Основной способ - `AbortController`. Его `signal` передается в `fetch`, а для отмены вызывается `controller.abort()`. Это полезно для таймаутов, смены страницы и отмены устаревшего запроса.

8. **Как работать с разными форматами данных?**  
JSON читается через `response.json()`, текст через `response.text()`, бинарные данные через `blob()` или `arrayBuffer()`. Для отправки формы можно использовать `FormData`, а JSON обычно отправляется через `JSON.stringify`.

9. **Как оптимизировать множество запросов?**  
Независимые запросы можно запускать параллельно через `Promise.all`. Повторные GET-запросы можно кэшировать. Также полезны отмена ненужных запросов, ограничение количества одновременных запросов и TTL для кэша.

10. **Лучшие практики Fetch API в production.**  
Нужно проверять `response.ok`, обрабатывать сетевые и HTTP-ошибки отдельно, использовать таймауты и отмену запросов, не хранить секретные токены в открытом клиентском коде, аккуратно делать retry только там, где это безопасно, и выносить повторяющуюся логику запросов в отдельные функции.
