# Ответы на вопросы к ПР13

1. **В чем разница между Promise.then().catch() и async/await с try/catch? Когда следует использовать каждый подход?**  
`then/catch` работает прямо с цепочкой промисов. `async/await` позволяет записывать асинхронный код почти как обычный последовательный код, а ошибки обрабатывать через `try/catch`. Для длинной последовательности операций обычно удобнее `async/await`, а для короткой цепочки можно использовать `then/catch`.

2. **Как работает Promise.all и что происходит, если один промис завершается ошибкой?**  
`Promise.all` запускает несколько промисов и возвращает их результаты в исходном порядке. Если хотя бы один промис завершается с ошибкой, итоговый промис сразу переходит в состояние `rejected`.

3. **Разница между Promise.all, Promise.race и Promise.allSettled.**  
`Promise.all` нужен, когда важны результаты всех успешных операций. `Promise.race` возвращает результат первого завершившегося промиса, например это можно применять для таймаута. `Promise.allSettled` ждет все промисы и возвращает статусы успешных и неуспешных операций.

4. **Как реализовать повторные попытки с экспоненциальной задержкой?**  
Операцию помещают в цикл. После ошибки перед новой попыткой выполняют задержку, которая увеличивается, например 500 мс, 1000 мс, 2000 мс. После последней неудачной попытки ошибка выбрасывается дальше.

5. **Что такое race condition и как его избежать?**  
Race condition возникает, когда итог программы зависит от того, какая асинхронная операция завершилась раньше. Для защиты можно контролировать порядок операций, отменять устаревшие запросы, хранить идентификатор актуальной операции или использовать очередь.

6. **Как работает кэширование асинхронных запросов?**  
Перед запросом проверяется, есть ли данные для этого URL в кэше. Если есть, возвращается сохраненный результат. Если нет, выполняется запрос и результат записывается в кэш. Также можно использовать TTL, ограничение размера и очистку устаревших данных.

7. **Как оптимизировать множество асинхронных операций?**  
Независимые операции можно запускать параллельно через `Promise.all`, повторяющиеся запросы кэшировать, ненужные запросы отменять и ограничивать количество одновременно выполняемых операций.

8. **Как обрабатывать ошибки в цепочках промисов?**  
Нужно использовать `catch` или `try/catch` и не оставлять отклоненные промисы без обработки. Если ошибка не может быть обработана на текущем уровне, ее следует повторно выбросить, чтобы она не была потеряна.

9. **Преимущества async/await.**  
Код читается последовательнее, проще использовать обычные `try/catch`, легче выполнять несколько зависимых шагов и отлаживать длинные асинхронные сценарии.

10. **Как отлаживать асинхронный код?**  
Полезны `console.log`, точки останова во вкладке Sources, вкладка Network для HTTP-запросов, просмотр Promise в консоли, вывод времени выполнения и проверка ошибок через `try/catch`.
