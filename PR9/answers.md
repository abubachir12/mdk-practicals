# Ответы на вопросы к ПР9

1. **В чем разница между O(n) и O(n²)?**  
O(n) означает, что время работы растет примерно линейно с количеством входных данных. Пример: поиск максимального элемента в массиве. O(n²) означает квадратичный рост времени. Пример: классическая пузырьковая сортировка с двумя вложенными циклами.

2. **Как работает бинарный поиск и почему O(log n)?**  
Алгоритм работает только с отсортированным массивом. На каждом шаге сравнивает искомое значение со средним элементом и отбрасывает половину оставшегося диапазона. Поэтому число шагов растет логарифмически.

3. **Плюсы и минусы пузырьковой сортировки.**  
Плюсы: простая реализация, легко понять принцип сортировки. Минусы: медленная на больших массивах, в худшем случае имеет сложность O(n²).

4. **Как оптимизировать проверку простого числа?**  
Достаточно проверять делители только до квадратного корня из числа. После проверки делимости на 2 можно проверять только нечетные делители.

5. **Рекурсивный и итеративный Фибоначчи.**  
Рекурсивная реализация короче, но простая версия выполняет много повторных вычислений и может переполнить стек. Итеративная версия быстрее и использует меньше памяти.

6. **Какие методы отладки использовались?**  
Использовались console.log, отдельные тесты для каждой функции, проверка крайних случаев и сравнение фактического результата с ожидаемым.

7. **Как работает алгоритм Евклида?**  
Пока второе число не равно нулю, первое заменяется вторым, а второе - остатком от деления первого на второе. Когда остаток станет нулем, текущее первое число является НОД.

8. **Какие edge cases нужно учитывать для массивов?**  
Пустой массив, один элемент, отрицательные числа, повторяющиеся значения, уже отсортированный массив, обратный порядок и поиск отсутствующего элемента.

9. **Как улучшить удаление дубликатов для больших массивов?**  
Можно использовать Set. В среднем это позволяет получить линейную сложность O(n), вместо повторного поиска через includes.

10. **Какие принципы чистого кода применены?**  
Понятные имена функций и переменных, одна задача на функцию, отсутствие лишнего дублирования, обработка крайних случаев, комментарии о сложности и отдельные тесты.
